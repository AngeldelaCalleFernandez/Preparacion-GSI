La tabla agrupa URLs; una misma página puede respaldar apartados distintos en las fichas individuales. Matices cotejados:

- Alt: alternativa según función y contexto; decorativa o redundante puede requerir alt vacío. No equivale a tooltip, nombre de archivo o descripción exhaustiva.
- HTML/CSS/JavaScript: responsabilidades predominantes, no exclusión absoluta de capacidades. CSS puede animar, HTML tiene interacción declarativa y JavaScript puede modificar DOM y estilos.
- Responsive: adaptación de un mismo documento al viewport/capacidades, no detección de cada modelo o simple reducción de lienzo. Media Queries Level 4 se cita con su estado CR Draft de 19-02-2026.
- Label: aporta identificación y nombre del control mediante asociación, no mera descripción adicional. for/ID o anidamiento, activación según plataforma y control, no validación o estilo.
- Elemento/atributo: el atributo pertenece al elemento y no es un contenedor autónomo. Los elementos vacíos no requieren contenido hijo.
- DOM: árbol e interfaces del documento frente a fuente, CSSOM y representación intermediaria de biblioteca. Se usa React solo como evidencia del ejemplo, sin recomendarlo o añadirlo a la aplicación.
- Living Standard: evolución de la especificación y snapshots no equivalen a disponibilidad inmediata de cada función en todo navegador.
- Semántica y tablas: apariencia no asigna por sí sola significado, nivel de encabezado o asociaciones de cabecera. Se adapta la estructura de tabla a su complejidad y se distingue layout de datos tabulares.
- HTML nativo y ARIA: roles no implementan automáticamente teclado o foco, ni la buena formación XML proporciona semántica web. No se prohíbe ARIA cuando procede.
- XML: vocabulario extensible frente a HTML/JSON y SGML más general. Se acota ese distractor para evitar que metalenguaje sin comparación sirva como segunda definición.
- Validez: buena formación, conformidad con un esquema y existencia de una referencia son propiedades distintas. XML 1.0 usa validez DTD; XSD es otro mecanismo con tipos más ricos.
- Documento XML completo tiene una raíz; comentarios e instrucciones no son raíces adicionales. Se distingue de fragmentos y entidades externas analizadas.
- Anidamiento: un ejemplo autocerrado es correcto; cruces, cierres ausentes y cierre sin apertura no lo son. No se usa recuperación HTML para validar XML.
- Error confirmado de MAN-GSI-P18-026: el feedback original repetía Elemento y Elemento, una comparación que no demuestra sensibilidad a caso. La propuesta usa Dato/dato en el mismo namespace; no cambia su clave.
- Atributos: comillas simples o dobles emparejadas, con reglas de contenido. No trasladar a XML la posibilidad de atributos HTML sin comillas.
- Entidades: &lt; es una referencia con nombre, distinta de referencia numérica, CDATA y prefijo. El carácter que resulta no se reinterpreta como apertura de marcado.
- DTD: restricciones y tipos propios, aunque más limitados que los de XSD. No son consultas XPath o transformaciones XSLT. Se fija versión de cada fuente sin trasladar límites de XSLT 1.0 a versiones posteriores.
