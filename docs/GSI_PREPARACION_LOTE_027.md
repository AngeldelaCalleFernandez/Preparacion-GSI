Matices y decisiones de fuente:

- Preparación el 28-10-2026. Las fuentes abiertas el 27-10-2026 conservan esa fecha real; DrilldownLevel y Rc se leen el 28-10-2026, y TypeScript se relee ese día para cotejar Strictness. No se presenta la reanudación como una nueva consulta de todas las URLs ni como revisión humana independiente.
- Eventos: manejadores y registro de señales no determinan compilación, interpretación o ejecución paralela. Se distingue el mecanismo descrito del sondeo explícito.
- Rust: propiedad y préstamos controlados principalmente al compilar; no GC trazador general obligatorio. Los contratos unsafe importan y unsafe no apaga todo el borrow checker. No se promete corrección lógica o rendimiento universal.
- TypeScript: tipado estático configurable, eliminación/transformación de sintaxis específica y JavaScript de ejecución. Las anotaciones no son validación de entradas ni prueba de ausencia de errores. No se adopta literalmente la afirmación del Handbook de que ningún runtime pueda admitir sintaxis TypeScript mediante sus propias herramientas.
- Métricas: primero significado y reglas comunes. La conservación de la pregunta 001 no modifica su microcaso, solo completa feedback y evidencia. Purview clásico respalda vocabulario, no se recomienda su interfaz; GOV.UK se usa para principios de calidad y finalidad, no obligaciones españolas.
- DSS/EIS: taxonomía clásica con familias solapadas. EIS puede ser DSS orientado a datos y tener análisis; por eso 002 pregunta por denominación general y 003 por orientación ejecutiva. Los textos de Power se acotan a conceptos, sin adoptar productos, cifras o navegadores históricos.
- CMI: objetivos, indicadores, metas e iniciativas relacionados con estrategia y perspectivas. No se confunde mapa causal con prueba empírica de causalidad o simple colección de gráficos.
- Top-down: se compara secuencia corporativa de integración y derivación de marts con entrega dimensional incremental. Kimball también tiene planificación corporativa top-down; bottom-up no significa marts inconexos ni falta de arquitectura. No se prescribe un enfoque universal.
- Staging: función temporal de recepción y preparación, no plazo fijo de borrado ni sustituto del histórico o modelo semántico. Se distinguen backroom y explotación sin imponer tecnología.
- Grano: se conserva la formulación 013; qué representa una fila puede ser evento o instantánea. No se reduce a cantidad de dimensiones, refresco o paginación. Las medidas deben ser coherentes con esa unidad de observación.
- Copo de nieve: normalización de dimensiones, no cambio de grano de hechos ni garantía de rendimiento. La fuente Power BI se usa para estructura y no se generalizan restricciones concretas del producto a todo modelo dimensional.
- OLAP: el caso de roll-up usa importes sumables. Drill-down requiere detalle disponible, no reconstruye datos ausentes. Pivot mantiene filtros/niveles para separar orientación y agregación. No se adoptan promesas comerciales de rapidez, capas infinitas o superioridad universal de MOLAP de la página IBM.
- Data mart: se pregunta por alcance organizativo/temático; un cubo es implementación posible y no otra respuesta al alcance. No se exige base física separada o DW corporativo previo en todo caso.
- ELT: carga y transformación principal en destino; puede haber controles y preparación previa. OLTP/MOLAP no definen ese orden. No se asume acceso directo seguro a datos brutos o ausencia de gobierno.
- Linaje: movimiento y transformaciones, condicionado por cobertura y metadatos. Se distingue glosario, sensibilidad y perfilado; no acredita exactitud por tener un diagrama. La referencia Purview clásica no prueba capacidades actuales de todos los conectores.
- ODS: datos operacionales recientes e integración, con menor historia habitual; no retención fija de un día ni prohibición de actualización frecuente en DW. Oracle 18c se usa solo para esa distinción estable.
- Conceptual: visión lógica global frente a perspectivas externas y archivos/páginas; el texto de Watt distingue también modelo físico y fases de diseño. Se evita atribuir una equivalencia universal entre su modelo interno y la terminología física de otras exposiciones. No se confunde el nivel con un namespace schema de SQL o permisos de roles.
- ROLLBACK: se conserva la formulación completa T05-004. Clasificar finalidad transaccional/consulta/DDL/autorización no niega que un motor incluya otras sentencias en transacciones. No se promete deshacer commits o efectos externos; no se ejecutó ninguna sentencia SQL.
