# Aplicaciones web. Desarrollo web front-end y en servidor, multiplataforma y multidispositivo. Lenguajes: HTML, XML y sus derivaciones. Navegadores y lenguajes de programación web. Lenguajes de script.

## Alcance del piloto {#alcance-piloto}

:::derivado
El piloto cubre la parte cliente mediante tres piezas trazables: HTML como lenguaje y sintaxis de documentos, XML 1.0 como lenguaje de marcado con reglas de buena formación y ECMAScript como lenguaje de programación de propósito general que puede actuar dentro de un entorno anfitrión. No desarrolla una arquitectura de servidor ni un navegador concreto.

## Aplicaciones web y separación conceptual {#aplicaciones-web}

:::explicacion
Desde el punto de vista del cliente conviene separar estructura documental y comportamiento programado. HTML forma parte de la plataforma web y define una sintaxis para documentos; ECMAScript define un lenguaje independiente del entorno anfitrión concreto. El entorno aporta objetos y servicios que la especificación del lenguaje no define por sí sola.

[[fuente:SRC-TECH-WHATWG-HTML-LS|localizador=#introduction]]
[[fuente:SRC-TECH-ECMA-262-2026|localizador=#sec-ecmascript-overview]]
:::

## Documentos HTML {#documentos-html}

:::resumen
Un documento HTML utiliza marcado para organizar contenido. La introducción del estándar presenta ejemplos formados por elementos delimitados mediante etiquetas y atributos asociados a esos elementos. El marcado expresa la estructura del documento; su presentación visual detallada queda fuera de este piloto.

[[fuente:SRC-TECH-WHATWG-HTML-LS|localizador=#introduction]]
:::

### Elementos, atributos y estructura {#elementos-atributos}

:::explicacion
Los elementos representan partes de la estructura y pueden contener texto u otros elementos. Los atributos aportan información vinculada al elemento de apertura. La anidación debe leerse como una relación estructural, no como una instrucción de programación.

[[fuente:SRC-TECH-WHATWG-HTML-LS|localizador=#introduction]]
:::

## Sintaxis y procesamiento básico de HTML {#sintaxis-html}

:::resumen
El estándar distingue la sintaxis HTML de la sintaxis XML. Un recurso servido como `text/html` se procesa como documento HTML. La especificación advierte que el tratamiento de errores de sintaxis no coincide con el de XML, por lo que no deben intercambiarse sus reglas de forma automática.

[[fuente:SRC-TECH-WHATWG-HTML-LS|localizador=#html-vs-xhtml]]
:::

## XML 1.0 y documentos bien formados {#xml-bien-formado}

:::explicacion
XML describe documentos compuestos por datos de caracteres y marcado. Un procesador XML lee el documento y proporciona a una aplicación acceso a su contenido y estructura. La especificación denomina bien formado al documento que satisface sus reglas sintácticas; la validez añade restricciones adicionales y no debe confundirse con la buena formación.

[[fuente:SRC-TECH-W3C-XML-1-0-5E|localizador=#abstract]]
[[fuente:SRC-TECH-W3C-XML-1-0-5E|localizador=#sec-intro]]
:::

## HTML frente a XML {#html-frente-xml}

:::derivado
HTML y XML son sintaxis distintas aunque ambas utilicen marcado. La fuente WHATWG explica que el tipo de medio determina si un documento se procesa como HTML o mediante un procesador XML y que sus reglas de error difieren. XML, por su parte, define restricciones de buena formación que el procesador debe tratar según la especificación.

[[fuente:SRC-TECH-WHATWG-HTML-LS|localizador=#html-vs-xhtml]]
[[fuente:SRC-TECH-W3C-XML-1-0-5E|localizador=#sec-intro]]
:::

## ECMAScript {#ecmascript}

:::resumen
ECMA-262 define ECMAScript 2026 como lenguaje de programación de propósito general. Su visión general explica que el lenguaje opera dentro de un entorno anfitrión, que aporta capacidades externas, y que su uso no queda limitado a un navegador. Por tanto, ECMAScript y las APIs particulares de un navegador son conceptos relacionados pero distintos.

[[fuente:SRC-TECH-ECMA-262-2026|localizador=#sec-scope]]
[[fuente:SRC-TECH-ECMA-262-2026|localizador=#sec-ecmascript-overview]]
:::

## Estructura, contenido y comportamiento {#estructura-contenido-comportamiento}

:::derivado
Para estudiar una aplicación web cliente puede usarse una separación conceptual: HTML organiza la estructura del documento; el contenido aparece dentro de esa estructura; ECMAScript expresa cálculos y comportamiento dentro de un entorno anfitrión. Esta separación es didáctica y no describe por sí sola toda la arquitectura cliente-servidor.

## Ejemplos didácticos {#ejemplos-didacticos}

:::ejemplo
Ejemplo didáctico de HTML original; representa estructura y contenido, no se ejecuta:

```html
<article>
  <h2>Aviso</h2>
  <p data-prioridad="alta">Contenido de ejemplo</p>
</article>
```
:::

:::ejemplo
Ejemplo didáctico de XML original y deliberadamente bien formado:

```xml
<?xml version="1.0"?>
<aviso prioridad="alta">
  <texto>Contenido de ejemplo</texto>
</aviso>
```
:::

:::ejemplo
Ejemplo didáctico de ECMAScript original; se muestra como texto y no se ejecuta:

```javascript
const aviso = { prioridad: "alta", visible: true };
const etiqueta = aviso.visible ? "Mostrar" : "Ocultar";
```
:::

## Glosario breve {#glosario}

:::resumen
- **Elemento HTML:** unidad estructural representada mediante marcado HTML.
- **Atributo:** información asociada a un elemento en su etiqueta de apertura.
- **Documento XML bien formado:** documento que cumple las restricciones sintácticas de buena formación de XML 1.0.
- **ECMAScript:** lenguaje de programación de propósito general definido por ECMA-262.
